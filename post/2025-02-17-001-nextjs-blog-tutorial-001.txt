10:T25c4,<h2 id="1-nextjs란0" tabindex="-1">1. Next.js란?</h2>
<p><strong>Next.js</strong>는 React 기반의 프레임워크로, 서버 사이드 렌더링(SSR)과 정적 사이트 생성(SSG)을 지원하여 성능과 SEO 최적화가 가능합니다.
파일 기반 라우팅, 서버 컴포넌트, API 라우트 등의 기능을 제공하며, React 애플리케이션을 더욱 효율적으로 개발할 수 있도록 돕는 프레임워크입니다.</p>
<p>우리는 블로그를 제작하기 위해 <strong>정적 사이트 생성(SSG)</strong> 기능이 필요하기 때문에 Next.js를 활용할 것입니다. 직접 구현할 수도 있지만, Next.js가 이미 최적화된 기능을 제공하므로 이를 이용하여 블로그를 제작해 보겠습니다.</p>
<p>먼저, Next.js를 설치하고 실행하는 방법을 살펴보겠습니다.</p>
<hr>
<h2 id="2-nextjs-설치-및-실행1" tabindex="-1">2. Next.js 설치 및 실행</h2>
<pre><code class="hljs language-bash">npx create-next-app@latest my-next-app
<span class="hljs-built_in">cd</span> my-next-app
npm run dev
</code></pre>

<h2 id="3-github-pages란4" tabindex="-1">3. GitHub Pages란?</h2>
<p><strong>GitHub Pages</strong>는 GitHub에서 제공하는 정적 웹사이트 호스팅 서비스입니다. 저장소의 코드를 기반으로 웹사이트를 자동으로 배포할 수 있어 블로그, 프로젝트 문서, 포트폴리오 사이트 등을 쉽게 구축할 수 있습니다.</p>
<h3 id="3-1-주요-특징5" tabindex="-1">3-1. 주요 특징</h3>
<ul>
<li><strong>무료 호스팅 제공</strong>: GitHub 계정만 있으면 무료로 사용 가능</li>
<li><strong>간단한 배포</strong>: GitHub 저장소에 코드 푸시만 하면 자동으로 사이트 업데이트</li>
<li><strong>정적 파일 지원</strong>: HTML, CSS, JavaScript 등 정적 콘텐츠 배포 가능</li>
<li><strong>커스텀 도메인 지원</strong>: 기본적으로 <code>https://&lt;username&gt;.github.io/</code> URL 제공, 맞춤 도메인 설정 가능</li>
</ul>
<h3 id="3-2-기본-사용법6" tabindex="-1">3-2. 기본 사용법</h3>
<ol>
<li>GitHub에서 새 저장소 생성</li>
<li>정적 파일(HTML, CSS, JavaScript) 또는 SSG 프레임워크(Next.js, Jekyll 등)로 생성한 파일 업로드</li>
<li>GitHub Pages 설정에서 브랜치 선택 후 활성화</li>
<li>배포된 사이트 URL 확인</li>
</ol>
<hr>
<h2 id="4-github-pages에서-정적-파일을-서비스하기-위한-설정7" tabindex="-1">4. GitHub Pages에서 정적 파일을 서비스하기 위한 설정</h2>
<p>GitHub Pages에서 정적 파일을 호스팅하려면 저장소를 미리 생성해야 합니다. GitHub에 로그인한 후 새 저장소를 만들고 아래와 같이 설정합니다.</p>
<ul>
<li><strong>저장소 이름</strong>: <code>&lt;username&gt;.github.io</code></li>
</ul>
<p>이렇게 설정하면 GitHub Pages의 기본 도메인 구조를 활용할 수 있습니다.</p>
<p><img src="/assets/post/2025-02-17-001-nextjs-blog-tutorial-001/create-repository.jpg" alt="create-repository"></p>

<h2 id="5-nextjs를-github-pages에-배포하기-위한-기본-설정8" tabindex="-1">5. Next.js를 GitHub Pages에 배포하기 위한 기본 설정</h2>
<h3 id="5-1-nextjs-프로젝트의-nextconfigjs-수정9" tabindex="-1">5-1. Next.js 프로젝트의 <code>next.config.js</code> 수정</h3>
<pre><code class="hljs language-js"><span class="hljs-keyword">const</span> nextConfig = {
  <span class="hljs-attr">output</span>: <span class="hljs-string">&quot;export&quot;</span>,
};

<span class="hljs-keyword">export</span> <span class="hljs-keyword">default</span> nextConfig;
</code></pre>
<p>위 설정을 적용하면 빌드 시 <code>out/</code> 디렉토리가 생성되며, 이 디렉토리를 GitHub Pages에 배포할 수 있습니다.</p>
<blockquote>
<p><strong>Note</strong>: <code>output: &quot;export&quot;</code> 옵션을 적용하면 Next.js의 렌더링 방식이 SSR(Server-Side Rendering)에서 SSG(Static Site Generation) 방식으로 변경됩니다.</p>
</blockquote>

<h2 id="nojekyll-파일-추가-css-깨짐-해결17" tabindex="-1">.nojekyll 파일 추가 (CSS 깨짐 해결)</h2>
<p>배포 후 CSS가 적용되지 않는 경우 <code>.nojekyll</code> 파일이 누락되었을 가능성이 있습니다.</p>
<p><img src="/assets/post/2025-02-17-001-nextjs-blog-tutorial-001/nojekyll-not-working.png" alt="nojekyll-not-working"></p>
<blockquote>
<p><strong><code>.nojekyll</code> 파일이란?</strong>
기본적으로 GitHub Pages는 Jekyll을 사용하며, <code>_next/</code> 같은 <strong>언더스코어(_)로 시작하는 폴더를 무시</strong>합니다.
Next.js, React, Vue 등의 정적 사이트를 배포할 때 <code>.nojekyll</code>이 없으면 CSS나 JS 파일이 정상적으로 로드되지 않을 수 있습니다.
따라서, <code>out/.nojekyll</code> 파일을 포함하여 배포해야 합니다.</p>
</blockquote>
<p>만약 <code>.nojekyll</code>이 push되지 않는다면 아래 명령어를 실행하세요.</p>
<pre><code class="hljs language-bash">git add -f out/.nojekyll
git commit -m <span class="hljs-string">&quot;Add .nojekyll&quot;</span>
git push origin gh-pages
</code></pre>
<p>또는, GitHub에서 직접 <code>.nojekyll</code> 파일을 추가하는 방법도 있습니다.</p>
<p><img src="/assets/post/2025-02-17-001-nextjs-blog-tutorial-001/add-nojekyll.png" alt="add-nojekyll"></p>
