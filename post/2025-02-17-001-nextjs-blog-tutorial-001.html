Next.js 블로그 만들기 - 0. 프로젝트 셋팅

1. Next.js란?

Next.js는 React 기반의 프레임워크로, 서버 사이드 렌더링(SSR)과 정적 사이트 생성(SSG)을 지원하여 성능과 SEO를 최적화할 수 있도록 설계되었습니다.
파일 기반 라우팅, 서버 컴포넌트, API 라우트 등의 기능을 제공하며, React 애플리케이션을 더욱 효율적으로 개발할 수 있게 만든 프레임워크입니다!

우리가 블로그를 제작하기 위해선 정적 사이트 생성(SSG) 기능이 필요하기 때문에 Next.js 프레임워크를 이용하는건데요 직접 구현을 할 수도 있지만, 깔끔하게 잘 만들어주는 녀석이 있기 때문에 블로그를 제작할 때는 Next.js를 이용해서 만들어보도록 하겠습니다.

(Vercel을 이용해 배포를 한다면 더 간단하겠지만, Vercel URL은 일부 회사들이 차단을 하고 있다고 하네요!)

먼저 간단하게 Next.js 설치 방법과 실행하는 법에 대해 설명하겠습니다.

3. GitHub Pages란?

GitHub Pages는 GitHub에서 제공하는 정적 웹사이트 호스팅 서비스로, 저장소의 코드를 기반으로 웹사이트를 자동으로 배포할 수 있습니다. 개인 블로그, 프로젝트 문서, 포트폴리오 사이트 등을 쉽게 구축할 수 있으며, Next.js와 같은 정적 사이트 생성(SSG) 기능이 있는 프레임워크와도 연동할 수 있습니다.

3-1. 주요 특징

  • 무료 호스팅 제공: GitHub 계정만 있으면 무료로 사용 가능.
  • 간단한 배포: GitHub 저장소에 코드 푸시만 하면 자동으로 사이트 업데이트.
  • 정적 파일 지원: HTML, CSS, JavaScript 등 정적 콘텐츠를 배포 가능.
  • 커스텀 도메인 연결 가능: 기본적으로 https://<username>.github.io/ 형식의 URL을 제공하지만, 원하는 도메인을 설정할 수도 있음.

3-2. 기본 사용법

  1. GitHub에서 새 저장소를 생성.
  2. 저장소에 정적 파일(HTML, CSS, JavaScript) 또는 정적 사이트 생성 프레임워크(Next.js, Jekyll 등)를 이용한 빌드 파일을 업로드.
  3. GitHub Pages 설정에서 브랜치 선택 후 활성화.
  4. 배포된 사이트 URL을 확인.

4. Github Pages에서 정적파일을 서비스하기 위한 설정

Github Pages에서 정적파일을 서비스하기 위해서는 아래와 같이 저장소를 미리 만들어두어야 합니다. Github에 로그인을 하여 새로운 저장소를 만들어 아래와 같이 입력합니다.

<username>.github.io 이름으로 저장소를 생성합니다.

5. Next.js를 GitHub Pages에 배포하기 위한 기본 설정

5-1. Next.js 프로젝트를 GitHub Pages에 배포하려면 next.config.js를 수정하여 out/ 디렉토리가 생성되도록 해야합니다.

js
const nextConfig = {
  output: "export",
};

export default nextConfig;

위의 output: "export" 옵션을 설정할 경우 빌드시 out/ 디렉토리가 생성됩니다. 추후 이 out/ 디렉토리를 Gihub 저장소에 배포를 하여 서비스를 할 예정입니다.

output:"export" 옵션을 설정할 경우에 렌더링하는 방식이 SSR(Server Side Rendering) 에서 SSG(Static Site Gernerating) 방식으로 바뀌게 됩니다.

6. Next.js 프로젝트를 Github 저장소에 Push

bash
cd my-blog
git init
git add .
git commit -m "first commit"
git remote add https://github.com/<username>/<username>.github.io
git push origin main

7. gh-pages로 명령어를 구성하여 간단하게 배포하기

Github에 블로그 소스코드를 업로드 하였습니다. gh-pages를 사용하여 gh-pages 브랜치에 배포하는 방법과 명령어를 구성하도록 하겠습니다.

7-1. gh-pages 패키지 설치

프로젝트에서 gh-pages를 사용하여 GitHub Pages에 배포하려면 먼저 패키지를 설치해야 합니다.

bash
npm install gh-pages --save-dev

7-2. package.json 수정 (배포 명령어 추가)

배포를 간편하게 하기 위해 package.json에 배포 스크립트를 추가합니다.

json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "next lint",
    "deploy": "npm run build && touch out/.nojekyll && gh-pages -d out"
  }
}

이 설정을 적용하면 next build 실행 시 out/ 디렉토리가 생성되며, 이 디렉토리를 GitHub Pages에 배포할 수 있습니다.

7-3. 배포 실행

이제 아래 명령어를 실행하면 자동으로 gh-pages 브랜치가 생성되며 GitHub Pages에 배포됩니다.

bash
npm run deploy

성공적으로 배포가 된다면 아래와 같이 gh-pages 브랜치가 생겨져 있는걸 확인할 수 있습니다.

7-4. GitHub Pages 설정

GitHub 저장소에서 Settings → Pages로 이동하여, Source를 gh-pages 브랜치로 설정하면 배포된 블로그를 확인할 수 있습니다.

7-5. 배포된 사이트 확인

배포가 완료되면, 아래 URL에서 블로그를 확인할 수 있습니다.

bash
https://<username>.github.io/

그런데 왜 CSS 적용이....

안되는 화면을 보실 수가 있습니다. 이유는 모르겠으나, out/ 폴더내부에 .nojekyll 파일을 만들어서 gh-pages 브랜치로 같이 배포를 해주어야 정상인데 이상하게 노지킬이 push되지 않았네요... 어떤 방식으로든 노지킬을 푸시 해보려 했으나 결국 못했습니다...

결국 해결방법으로 리포지토리 페이지로 접속해서 add file 버튼을 눌러 직접 추가해주었습니다...

.nojekyll의 역할? .nojekyll은 GitHub Pages에서 Jekyll 처리를 비활성화하는 파일입니다.
기본적으로 GitHub Pages는 Jekyll을 사용하며, _next/ 같은 언더스코어(_)로 시작하는 폴더를 무시합니다.
Next.js, React, Vue 등의 정적 사이트를 배포할 때 .nojekyll이 없으면 CSS나 JS 파일이 정상적으로 로드되지 않을 수 있습니다.
따라서, out/.nojekyll을 반드시 포함하여 배포해야 합니다.
만약 .nojekyll이 push되지 않는다면 git add -f out/.nojekyll을 사용하거나 GitHub에서 직접 추가하면 해결됩니다. 🚀

이제 GitHub Pages를 통해 Next.js 블로그를 간편하게 배포할 수 있습니다!
