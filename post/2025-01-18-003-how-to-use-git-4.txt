# Git 사용법: 로그와 히스토리 관리 & 태그 사용법

## 7. Git 로그와 히스토리 관리

Git은 파일 변경 이력을 철저히 관리합니다. 적절히 로그와 히스토리를 활용하면 특정 시점의 코드 상태를 이해하고, 문제 해결에 필요한 정보를 빠르게 찾을 수 있습니다.

### 커밋 히스토리 확인

Git의 모든 커밋 이력을 확인하려면 아래 명령어를 사용하세요.

```bash
git log
```

#### 옵션을 활용한 로그 출력

- **간단히 보기**: 커밋 메시지와 ID를 한 줄로 표시.
  ```bash
  git log --oneline
  ```
- **그래프 형태로 보기**: 브랜치와 병합 내역을 시각적으로 확인.
  ```bash
  git log --graph
  ```
- **특정 파일의 변경 기록 확인**:
  ```bash
  git log -- <파일명>
  ```

### 특정 커밋 확인

특정 커밋의 상세 내용을 확인할 때는 아래 명령어를 사용합니다.

```bash
git show <커밋 ID>
```

이 명령어는 해당 커밋에서 수정된 파일과 변경 내용을 보여줍니다.

---

## 8. Git 태그 사용법

태그(Tag)는 프로젝트에서 특정 시점을 표시하거나, 중요한 상태(예: 릴리스 버전)를 기록할 때 유용합니다. 일반적으로 소프트웨어 버전 관리에 많이 사용됩니다.

### 태그의 종류

1. **Annotated Tag (주석 태그)**: 메타데이터와 서명을 포함하여 저장.
2. **Lightweight Tag (경량 태그)**: 단순히 커밋을 가리키는 포인터 역할.

### 태그 생성

- **Annotated Tag 생성**:

  ```bash
  git tag -a <태그명> -m "태그 설명"
  ```

  예시:

  ```bash
  git tag -a v1.0 -m "첫 번째 릴리스"
  ```

- **Lightweight Tag 생성**:
  ```bash
  git tag <태그명>
  ```
  예시:
  ```bash
  git tag v1.0
  ```

### 태그 확인

저장소의 모든 태그를 나열합니다.

```bash
git tag
```

### 태그 푸시

원격 저장소에 태그를 푸시하려면 아래 명령어를 사용합니다.

```bash
git push origin <태그명>
```

모든 태그를 푸시하려면:

```bash
git push origin --tags
```

### 태그 삭제

- **로컬 태그 삭제**:

  ```bash
  git tag -d <태그명>
  ```

- **원격 태그 삭제**:
  ```bash
  git push origin --delete <태그명>
  ```

---

## 마무리

Git의 **로그와 히스토리 관리**를 활용하면 프로젝트의 전체 흐름을 정확히 이해할 수 있고, **태그**를 적절히 사용하면 중요한 시점을 명확히 관리할 수 있습니다. 특히 팀 협업 환경에서는 이러한 기능이 코드 안정성과 효율성을 높이는 데 큰 기여를 합니다. 🎯
